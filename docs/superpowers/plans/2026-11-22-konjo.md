# Konjo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PWA móvil para rachas de hábitos con foto de prueba, amigos, retos 1 a 1 con multas registradas en un ledger, resumen con gráficas y notificaciones.

**Architecture:** Next.js (App Router, TypeScript) en Vercel + Supabase (Auth, Postgres con RLS, Storage, pg_cron + pg_net). Toda la lógica de rachas, períodos y saldos vive en `src/domain/` como funciones puras testeadas con Vitest; la base guarda hechos (check-ins, deudas) y nunca contadores derivados. Las tareas programadas son route handlers de Next (`/api/cron/*`) que `pg_cron` llama cada 15 minutos vía `pg_net` con un secreto, para reutilizar `src/domain/` (cambio respecto del diseño, que decía Edge Function: misma función, una sola fuente de lógica).

**Tech Stack:** Next.js 15, React 19, TypeScript strict, Tailwind CSS v4, `@supabase/ssr`, `@supabase/supabase-js`, `@date-fns/tz` + `date-fns`, Recharts, `browser-image-compression`, `web-push`, Serwist (`@serwist/next`), Vitest, pgTAP (`supabase test db`), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-22-konjo-design.md`

## Global Constraints

- Idioma de la interfaz: español. Moneda CLP, montos enteros, formato `$5.000` (`Intl.NumberFormat('es-CL', { style: 'currency', currency: 'CLP' })`).
- Prohibidas en la UI las palabras "apuesta", "bet", "pozo". Usar "reto", "multa", "deuda".
- Estilo Fuzz `calm-utility`: bg `#FAFAFA`, surface `#FFFFFF`, line `#E6E6E6`, text `#111111`, muted `#6F6F6F`, accent `#5A5AC2`, accent2 `#2E3A5E`, alert `#E5484D`; Inter, Geist Mono para números; radio 10px.
- Navegación inferior fija: Hoy · Amigos · Retos · Resumen · Perfil. Diseño mobile-first; probar a 375px de ancho.
- Semanas de lunes a domingo. Fechas locales como `YYYY-MM-DD` (string), instantes en UTC (`timestamptz`).
- Ventana de rechazo de foto: 24 h desde `created_at` del check-in.
- Edad mínima 18 (autodeclarada). Fotos en bucket privado `proofs`, URLs firmadas de 300 s, sin EXIF.
- No correr `next build` (regla del dueño). Verificar con `pnpm test`, `pnpm typecheck`, `pnpm lint`, `supabase test db`.
- Commits: conventional commits, sin atribución a IA. **Pedir confirmación al dueño antes de cada commit.**
- Strict TDD: cada tarea escribe el test que falla antes del código.

## Review Focus

1. **Cambio de zona horaria o viaje en medio de una racha:** la racha se calcula sobre `local_date` guardado al hacer check-in; fechas duplicadas o desordenadas no rompen el cálculo. Test en Task 2.
2. **Doble toque en "Hecho" o reintento de subida:** un solo check-in por hábito y día local; el segundo devuelve el existente. Test en Task 5 (constraint) y Task 7 (acción).
3. **Rechazo de foto fuera de plazo o de un período ya cerrado:** se rechaza después de 24 h; un período no se cierra con fotos dentro de su ventana. Tests en Task 3 y Task 9.
4. **Usuario que no es amigo intentando ver fotos o check-ins:** RLS de tablas y de Storage lo bloquea. Test en Task 5.
5. **El cron corre dos veces o se cae a la mitad:** las deudas no se duplican (unique `challenge_id, period_start, debtor_id`). Test en Task 10.
